# 図面解析タブ

図面を開いて最初に触るタブです。拾いを始める前の「読む」工程 —— 特記仕様書・凡例・機器表・配線表・注記を読み、何を拾うか（パレット）を決め、どのページで拾うかを決める —— を、Gemini に一度に下書きさせ、人が確かめて直します。

## 流れ

1. **送るページを選ぶ** — 左の一覧の「送る」、または番号（`1-3, 11, 36`）。仕様書・凡例・系統図・機器表のあるページ・拾う平面図など。全部は要りません（電気設備だけでも 100 ページを超える図面があるため）
2. **読みどころを囲む（注釈）** — 上の帯の筆（キー 1〜9）で図面を囲みます。種類は下の表。囲んだ範囲は、解析のときに細かく切り抜いて画像で送ります
3. **解析する** — 送るページを切り出した PDF ＋ 注釈の切り抜きを、Gemini に 1 回で渡します。返ってきたものは、そのまま入ります（元に戻す 1 回で、まとめて戻せます）
4. **確かめて直す** — ページの欄・パレットの画面・覚え書き。解析が書いた値には「AI」の印。左の「未確認」でページを絞れます
5. **拾いのタブへ** — 「拾う」の印のページだけが出ます（1 枚も無ければ全部）。図面の上の「参照 ▾」で、注釈の範囲（器具表など）を小窓に出して照らし合わせながら拾えます

## 注釈の種類

| 種類 | 囲むもの | 解析が作るもの |
| :-- | :-- | :-- |
| 仕様書 | 特記仕様書・共通事項 | 対象の範囲（採用の●・不採用）、図に描かれない部材の決まり（覚え書き） |
| 凡例 | 記号と名称、線種と敷設方法 | カテゴリの中くらいの段（記号の形で見分ける分類）と葉、ラベルの木「敷設」 |
| 機器表 | 器具表・姿図・盤表・機器リスト | 部材（葉）と仕様。部屋ごとの台数があれば、部屋の節の規則と見込み |
| 配線表 | 幹線・動力・制御などの配線の一覧 | 配線の書き方ごとの葉と構成（ケーブル・電線・電線管と本数）、系統（番号・起点・終点） |
| 注記 | その図面だけの決まり | 規則・構成の条件・覚え書き |
| 層の手がかり | 部屋名・区画・敷設の範囲 | ラベルの節 |
| 対象の見本 | 拾うものの例（記号、ラック・盤のような広い対象も） | それが何か（カテゴリ）と数え方 |
| 注意 | 範囲外・既設・別途工事・食い違いの疑い | 覚え書き（注意）。範囲外のものはカテゴリにしない |
| 題欄 | 図面名称・番号の枠 | ページの題。「全ページ」にすると、送る全ページの同じ位置を切り抜いて添える |

注釈ごとに「機械への覚え書き」（例: この表は 1 階だけ／記号の横の数字は回路番号）を書けます。解析はこれを指示として読みます。
「解析」の欄の「今回の範囲・伝えること」（例: 今回は電灯設備と照明器具だけ）を書くと、範囲の外の設備はパレットに入りません。

## 解析が入れるもの

| もの | 置き場 | 人が直す所 |
| :-- | :-- | :-- |
| ページの分類（題・図面番号・種類・工事種目・階・縮尺・要約・拾う） | ページ | 図面解析のタブ → 右の「ページ」。人が直した欄は、次の解析で替えない |
| カテゴリ（部材の木）・構成 | パレット | パレットのタブ → 部材カテゴリ（メモ・出どころも出る） |
| ラベルの木と節・規則 | パレット | パレットのタブ → 層のラベル・規則の一覧 |
| 見込み（表に書いてある個数） | パレット | パレットのタブ → 見込み。集計のタブの「照合」で置いた数と比べる |
| 系統（配線表の行） | パレット | パレットのタブ → 系統。線の名前の候補になり、名前を選ぶと線のカテゴリもその行の配線になる。引いた本数で消し込む |
| 覚え書き（範囲・図に無い部材・決まり・系統・注意・食い違い） | 作業 | 図面解析のタブ → 右の「覚え書き」。拾いのタブでも、そのページの分が右に出る |

パレットへは**足し合わせ**で入ります（同じ親の下の同じ名前は、いまのものを使う）。同じ応答をもう一度入れても増えません。

## 送るもの・鍵

- 送り先は Google の Gemini API（`generativelanguage.googleapis.com`）だけです。ブラウザから直に送ります（このツールにサーバーはありません）
- 鍵は「解析」の欄で入れます。このブラウザの localStorage にだけ保存します
- PDF は、送るページだけを [pdf-lib](https://pdf-lib.js.org/) で切り出して送ります（画像にしない）。14 MB を超えるときは Files API で上げ、使い終わったら消します
- 切り抜きは pdf.js で描いた PNG（300 dpi を基本に、長い辺 1,536 画素まで。大きい範囲は分けて送る）
- 送る前に、送るものの一覧を出して確かめます。最後の応答はブラウザ（IndexedDB）に残り、「最後の応答をもう一度入れる」で送り直さずに入れ直せます

## 頼み方について分かったこと（2026-10-02 の実験）

社内のサンプル図面（A3・76 ページ。文字の層が無く、字も線で描かれている PDF）で、`gemini-3.8-flash` に同じ頼みを条件を変えて投げて比べました。

| 条件 | 結果 |
| :-- | :-- |
| PDF だけ（1 ページの PDF に器具表がある） | PDF は 1 ページ約 1,100 トークン（`MEDIA_RESOLUTION_HIGH`。既定は約 530）で読まれ、表の細かい字は読めない。器具表の部屋は 37 のうち 0〜1 しか合わず、記号を作り話にした。`ULTRA_HIGH` は PDF には指定できない |
| 同じ表を 300 dpi の切り抜きで | 37 部屋・181 台が全部合った |
| 一発（6 ページの PDF ＋ 切り抜き）・考える量「少なめ」 | 45〜60 秒。題 6/6、拾うの印 6/6、部屋の規則と見込み 36/37。配線表は 62 行のうち 45 系統 |
| 同じ・考える量「多め」 | 約 3 分。62 系統すべて、配線の葉 26・構成 38。器具表どうしの食い違いを覚え書きに挙げた |
| 注釈なし（PDF だけ）で一発 | 題・拾うの印は合う（題欄の字は大きい）が、部屋の規則 0/37、系統 5 |
| 道具の考え方を書かない短い指示（応答の形は同じ） | 部屋の規則 27/37、系統 4。カテゴリ・規則・構成の意味を説明する指示が効く |
| 自動火災報知設備のページ（凡例・系統図・平面図） | 感知器・発信機・受信機などの木と、別途工事の区分・敷設の決まりを読んだ。範囲を書かないと、凡例にある別の設備（照明・接地極など）もカテゴリになる → 「今回の範囲」の欄を足した。「今回は自動火災報知設備だけ」と書くと、カテゴリの根は 自動火災報知設備・部材 の 2 つになった（書かないときは 9 つ） |
| 76 ページ全部（34.6 MB。Files API で上げる）を注釈なしで・考える量「少なめ」 | 約 3 分。出力の上限（65,536 トークン）に届いて切れた。系統の欄で、読めない字「？」の繰り返しに入っていた。切れる前までを読む形（`salvage`）にすると、ページの分類 76 枚が取れ、題は 64/76（1 ページずつ縮小画像で読ませた前の試作では 51/76）、拾うの印は 72/76（外れ 4 枚は単線結線図・動力盤結線図で、拾うかは決めの問題）。カテゴリは 21 だけ。→ 指示に「読めない行は書かない・繰り返さない」を足し、ページが多く注釈が無いときは画面で知らせる |
| 照明器具姿図のページ全体を注釈に（12 枚に分けて送る） | 器具の記号ごとに、消費電力・光束・メーカー・型番まで仕様（メモ）に入った |

ここから決めたこと:

- PDF は全体の把握（ページの種類・題・図の内容）、細かい字は注釈の切り抜き、と分担する
- 指示には、道具の考え方（カテゴリ・構成・ラベル・規則・見込み・系統）を書く。応答は決まった形（JSON スキーマ）で受け、key で互いを指させ、パレットへの組み立てはコード（`core/analysis.js` の `apply`）で行う
- 「表は全部の行を読む。省略しない」と書く。考える量の既定は「多め」
- 応答の欄の順を決める（`propertyOrdering`: ページ → 覚え書き → 系統 → ラベル → カテゴリ → 構成 → 規則 → 見込み）。6 ページ＋注釈 8 件・考える量「多め」で、決める前は出力の上限に届き（約 5 万トークン・195 秒）、最後に来る系統と覚え書きが 0 件になった。順を決めて仕様（メモ）を 60 字までにすると、163 秒・出力 3.1 万トークンで切れずに終わり、系統 62・覚え書き 12・カテゴリ 145・規則 37・見込み 38 が入った（ブラウザから。2026-10-02 03:0x）
- 応答が途中で切れても、読めたところまでは入れる（知らせを出す）。ページの分類だけなら、全ページの PDF を一度に送ってもよい。パレットは、ページを絞って注釈で読ませる
- 誤りは残る（器具 1 つの読み違いなど）。だから全部の結果を人が直せる形で入れ、出どころ（切り抜きの札・ページ）を残す

| `core/analysis.js` | 注釈の種類・ページの欄・注釈と覚え書きの編集、送るものの計画（切り抜きの分け方）、頼む文と応答の形、応答をパレットへ入れる |
